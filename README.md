# Oct Cafe ☕

A fun, free home-cafe web app for parties. Guests scan a QR code, pick drinks & bakery (no prices, no payments), and the host runs a kitchen board on a tablet or laptop.

Orders are shared over a tiny Node server that writes `orders.json` — any phone on the same Wi‑Fi can order into the same kitchen board.

## Quick start

```bash
cd /workspace/home-cafe
npm install
npm start
```

Then open the **Local** or **LAN** URL printed in the terminal (default port **3847**).

| Page | Path |
|------|------|
| Guest menu | `/` |
| Kitchen board | `/kitchen` |
| QR code | `/qr` |

## Share on LAN (party mode)

1. Run `npm start` on the host computer (the one that stays on during the party).
2. Note the **LAN** line, e.g. `http://192.168.1.42:3847`.
3. Put guest phones and the kitchen tablet on the **same Wi‑Fi**.
4. Guests open the LAN URL (or scan the QR). Kitchen opens `/kitchen` on that same host URL.

**Firewall tip:** allow inbound TCP on port `3847` if phones can’t connect.

**Caveat:** `localhost` / `127.0.0.1` only works on the host machine. Phones must use the LAN IP.

## QR code

- Open `/qr` on the host using the **LAN** URL (so the QR encodes that address).
- Or paste any URL into the field on `/qr` and click **Update QR**.
- Or generate one externally: [qr-code-generator.com](https://www.qr-code-generator.com/) with your LAN URL.

Print the QR page or display it on a tablet by the door.

## Edit cafe name & menu

Everything editable lives in one file:

**`menu.json`** (project root, next to `server.js`)

```json
{
  "cafeName": "Oct Cafe",
  "welcome": "Your short welcome message…",
  "sections": [
    {
      "id": "drinks",
      "title": "Drinks",
      "items": [
        {
          "id": "house-drip",
          "name": "House drip",
          "description": "…",
          "emoji": "☕",
          "tags": ["hot", "caffeine"]
        }
      ]
    }
  ]
}
```

- Change `cafeName` and `welcome` for branding.
- Add/remove sections (Drinks, Bakery, Savoury, …).
- Each item: `id`, `name`, `description`, `emoji`, optional `tags`. **No prices.**
- Restart is **not** required for menu edits — refresh the guest page (menu is read from disk on each `/api/menu` request).

## Order flow

1. Guest taps **+ / −** for quantities.
2. Opens **Order**, enters name + optional notes.
3. Submit → `POST /api/orders` → saved in `orders.json`.
4. Kitchen board polls every ~3s; host taps status: **new → making → ready → done**.

## API (simple)

| Method | Path | Body |
|--------|------|------|
| `GET` | `/api/menu` | — |
| `GET` | `/api/orders` | — |
| `POST` | `/api/orders` | `{ guestName, notes, items: [{ id, name, emoji, qty }] }` |
| `PATCH` | `/api/orders/:id` | `{ status: "new"\|"making"\|"ready"\|"done" }` |
| `DELETE` | `/api/orders` | clears **done** (use `?all=1` to wipe all) |

## Persistence notes

- **Preferred (this app):** Node Express + `orders.json` — all devices on the LAN share one backend.
- localStorage-only would require kitchen + guest on the **same browser/device**; we don’t rely on that.
- `BroadcastChannel` is only useful for multiple tabs on the same origin in one browser; the server + polling is what keeps phones and kitchen in sync.
